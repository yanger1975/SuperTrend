技術棧與系統架構說明

SuperTrend Trading Performance Tracking System Technical Stack

系統高階架構

本系統採用高度解耦的模組化 Package 設計。核心回測與數學計算完全獨立於執行入口，支援單員測試、Jupyter Notebook 互動分析與 CLI 多標的批次平行運算。系統整合 SQLite 本地資料庫，同時實現歷史 K 線快取、最優參數持久化及最新交易訊號管理。

[CLI / Jupyter / GitHub Actions] ──(1) 呼叫資料庫／網路──> [data_loader.py] (run_batch_optimization_supertrend_ai.py) │ (run_daily_scanner.py) 優先檢索/增量快取 (run_optimization.py) v [storage.py] (SQLite DB) [optimizer.py / supertrend_ai] <──(2) 網格優化 & 回測 ──────┘ │ (3) 產出報告 & 訊號存庫 ├─── Telegram 報告 ──────> [telegram_notifier.py] ──> Telegram Bot API (含 Pages 網址) ├─── Markdown 報告 ──────> data/{date}/{ticker}.md / All.md ├─── JSON 訊號與參數版控 ─> data/latest_signals_ai.json & optimized_params_ai.json ├─── GitHub Pages 儀表板 ─> [src/supertrend_ai/html_generator.py] ──> public/index.html └─── 持久化寫入 ──────────> strategy_params_supertrend_ai & stock_signals

模組職責定義

1. 本地資料儲存層 (src/storage.py)

  • 建立與初始化 SQLite 資料庫 (`data/market_data.db`)，預設啟用 **WAL 模式 (`PRAGMA journal_mode=WAL`)** 與 **busy_timeout (10,000ms)**，並實作指數退避重試 (`_execute_with_retry`) 防止多執行緒/進程併發寫入鎖定 (`database is locked`)。
  • **`price_history` 表格**：實作 `upsert_prices` 方法，使用 `(ticker, interval, datetime)` 主鍵避免重複資料。針對共同基金，Open/High/Low/Volume 補 0.0，Close 為每日淨值 (NAV)。
  • **`ticker_info` 表格**：實作 `upsert_ticker_info` 與 `get_ticker_info`，儲存標的元數據 (中文全名 `name`、資產類別 `asset_type='fund'|'etf'|'stock'`、資料來源 `source='ezmoney'|'yfinance'`)。
  • **`supertrend_params` 表格與 JSON 單向持久化**：實作 `save_supertrend_params` 與 `query_supertrend_params`，儲存各標的最適參數 (`ST_Period`, `ST_Multiplier`, `MA_Period`, `Use_HMA_Filter`) 及風控回測指標；並採用暫存檔寫入 + `os.replace` 原子替換機制將參數同步至 `data/optimized_params.json`。在 GitHub Actions 等 CI/CD 無狀態環境中自動從 JSON 恢復。
  • **`stock_signals` 表格**：實作 `save_stock_signals` 與 `query_stock_signals`，儲存標的最新持倉狀態 (`1=long`, `0=cash`)、進場參考點 (`entry_ref`)、出場參考點 (`exit_ref`)、`close_price` 與 `hma` 數值。

2. 資料協調載入器 (src/data_loader.py)

  • 協調儲存層與 yfinance / EzMoneyScraper / TwseScraper API。若本地快取已有資料則直接讀取；當偵測到以 .EZ 結尾之基金時調用 EzMoneyScraper；當偵測到以 .TW 結尾或於 data/must_have_tw.json 之台股標的時，自動透過 yfinance (auto_adjust=True) 下載完整除權息還原日 K 線並儲存標的元數據至 ticker_info。
  • **台股除權息還原與 TWSE 即時補丁融合機制 (`patch_twse_data_if_needed`, `get_latest_dividend_date`)：** 依據除權息調整數學原理，在最新除息日之後的價格未受折價影響（原始成交價與還原價 100% 精確相等）。當偵測到 yfinance 台股資料落後最新交易日且缺漏區間在最新除息日之後時，系統自動向證交所 OpenAPI 或月度日線無縫補齊最新數據，徹底消除 Yahoo Finance 針對台股 1 天的更新延遲，同時杜絕除息跳空誤判。
  • **台股盤後 14:30 前未結算日 K 線防禦：** 當前台北時間在 14:30 盤後正式結算前，所有台股標的 (.TW 與 .EZ) 結束日期強制鎖定為前一營業日（昨日），並自動自 yfinance 與快取中剔除當日未成形即時 Bar，防止晨間報告誤將早盤即時行情寫入歷史日線資料庫。
  • 提供防錯校正機制，修復不合邏輯的 K 線價格 (如 High < Close)，並針對共同基金淨值資料自動補齊 Open/High/Low 等同於 Close 淨值，確保指標運算與回測流程相容。
  • **1 小時 (1-Hour) 自動截斷與日誌警告：** 當請求 1 小時頻率且指定日期區間超過 730 日時，自動將起始日期限制在 730 日內並發出日誌警告。

3. 數據爬蟲模組層 (src/scrapers/)

  • **EzMoneyScraper (src/scrapers/ezmoney_scraper.py)**：自動處理 ASP.NET CSRF 防偽權杖 (__RequestVerificationToken) 擷取、Session 資源自動釋放、民國/西元日期雙向轉換、HTML 淨值表格邊界與資料合法性校驗，並儲存標的元數據至 ticker_info。
  • **TwseScraper (src/scrapers/twse_scraper.py)**：臺灣證券交易所 (TWSE) 官方數據工具，實作三端點融合架構：(1) /exchangeReport/STOCK_DAY 按月抓取歷史 K 線含 3.0 秒安全間隔與指數退避重試；(2) OpenAPI /v1/exchangeReport/STOCK_DAY_ALL 每日盤後快照；(3) TWSE MIS 即時行情系統 (mis.twse.com.tw)：透過 fetch_realtime_quotes 與 get_realtime_bar 於開盤時段批次查詢上市 (tse_) 與上櫃 (otc_) 最新成交價、五檔買賣價量、開高低與累積量，當暫時無成交時自動以買賣一檔中間價 (bid+ask)/2 安全估算。

4. 技術指標計算器 (src/indicators.py)

  • 使用 Pandas / NumPy 向量化運算計算 SuperTrend 指標。
  • 計算 HMA (Hull Moving Average) 均線過濾器、ADX 趨勢強度與 RSI 動能指標。

5. 盯市回測引擎 (src/backtest_engine.py)

  • 實作 K 線逐根迭代交易模擬器，支援手續費與滑價計算。
  • **盯市模型 (Mark-to-Market)：** 每日更新持倉淨值，真實反映持倉期間的回撤與波動。
  • **跳空 (Gap) 處理：** 若開盤價直接跳空突破止損價，以 Open 價成交。

6. 風險管理器 (src/risk_manager.py)

  • 計算 CAGR, Max DD, Sharpe, Sortino, PF, Calmar, Expectancy 與 Ulcer Index (潰瘍指數)。
  • 執行 Trade-level Monte Carlo 模擬，支援指定 Seed 重現，評估 95% 及 99% 風險分位數。

7. 參數優化器 (src/optimizer.py)

  • 進行多維度參數網格搜尋，支援樣本內/外 (Walk-Forward) 驗證。

8. 執行腳本與報告生成 (run_batch_optimization.py & run_optimization.py)

  • **多標的批次執行 (`run_batch_optimization.py`)**：自動收集標的（Most Active + Must Have），採用多執行緒並行跑優化與回測。
  • **報告生成**：自動產出個股 Markdown 報告與 `All.md` 全標的總覽報告（`long` 持倉標的自動置頂排序），並對檔案名稱進行安全過濾。

9. Telegram 通知發送模組 (src/telegram_notifier.py)

  • 封裝 Telegram Bot API，支援 HTML 格式化訊息、內建 `escape_html()` 轉義防止標籤注入，以及動態 API URL 安全隱藏 Bot Token。
  • **長訊息分拆**：自動將超過 3,500 字元之診斷報告切分成多段發送，防止超過 Telegram API 上限。

10. 每日交易訊號掃描腳本 (run_daily_scanner.py)

  • **標的與優化判斷**：每日掃描熱門美股與必備標的，新標的自動網格優化，舊標的搜尋與目前日期最近 end_date 之最適參數，每週六自動執行全標的重新優化。
  • **訊號變動追蹤**：比較前日與當日持倉狀態，精準辨識 `NEW_BUY` (新進場)、`NEW_SELL` (新平倉/止損)、`HOLD_LONG` (持倉中) 與 `WAIT_CASH` (觀望標的) 並發送報告。

11. SuperTrend AI 動態尋優模組 (src/supertrend_ai/)

  • **動態因子選擇 (Numba JIT 加速)**：我們採用 Numba `njit` 重寫了 1D KMeans 演算法 (`kmeans.py`) 取代原先的 `scikit-learn`，大幅度解決了逐根 K 線即時運算的效能瓶頸。該模型依據過去歷史績效 (Performance Memory) 進行自動分群 (預設 3 群)，選取最適當下盤勢的動態因子。
  • **詳細參數與調整教學**：AI 版由於具備動態調整與多空支援，參數組合較多（包含 `lengths`, `min_mults`, `max_mults`, `perf_alphas`, `long_onlys` 等），詳細的擴充與調整指南請參閱 SuperTrend AI 參數說明與調整指南。
  • **取樣頻率調整 (Downsampling)**：除了 Numba 的底層加速，我們還加入了 `update_freq` 參數。預設為 `1` (每根 K 線皆重新運算)，若在超大資料集下需要提升效能，可將參數調整為 `5` 或 `10`，代表每 5-10 根 K 線才重新聚類一次，在稍微犧牲即時性的情況下取得極致效能。
  • **網格優化與回測報告**：內建 `optimizer.py` 用以掃描最佳學習參數 (例如學習長度與目標群集)，並透過 `reporter.py` 生成包含逐月報酬率矩陣的詳細 Markdown 回測報告。
  • **獨立儲存**：新設 `strategy_params_supertrend_ai` 表格專門儲存此機器學習策略之最適參數 (包含 `update_freq` 欄位)，達成與傳統策略資料互不干擾的擴充架構。
  • **雙市場獨立 Telegram 訊號推播**：整合 data/must_have.json（美股）與 data/must_have_tw.json（台股與國內基金），自動辨識市場類型並分流發送兩則獨立的 Telegram 診斷訊息（分別呈現美股與台股各自的最新市場交易日與專屬貨幣符號）。

12. 靜態儀表板生成引擎 (src/supertrend_ai/html_generator.py)

  • **自包含純 Python 渲染**：零依賴純 Python 標準庫，自 data/latest_signals_ai.json 與 data/optimized_params_ai.json 直接編譯生成單檔 public/index.html，無需 Node.js / npm 等額外前端建置步驟。
  • **多維度科技儀表板介面**：深色主題設計，支援美股與台股/基金 Tab 切換、雙核心表格（最新訊號與進出場價格表、最適參數與評分表，明確揭示 Score、Win Rate、CAGR、Max DD 與 Sharpe）、標頭點擊升降冪排序與即時搜尋過濾。
  • **原生 GitHub Pages 整合**：由 daily_supertrend_ai_signals.yml 自動調用生成並透過 actions/deploy-pages 發布，不污染 Git 主分支歷史。

13. 台股盤中即時訊號監控模組 (run_intraday_tw_signals.py)

  • **盤中 13:10 極速純推論 (Inference-Only)**：於台北時間平日 13:10 (UTC 05:10) 自動由 GitHub Actions 排程觸發，直接載入已存最佳化參數，跳過繁重網格搜尋，數秒內完成全標的 SuperTrend AI 訊號計算。
  • **記憶體虛擬 K 線拼接 (零污染原則)**：自本地 SQLite 載入截至昨日之已結算日 K 線，於記憶體中將 TWSE MIS 當日即時 Bar 追加至末端；不覆寫、不污染 SQLite 歷史資料庫，實現未收盤暫態與正式結算的徹底解耦。
  • **高優先級行動指示告警**：自動比對昨日與今日部位變化，精準辨識【🟢 盤中突破買進 (NEW_BUY)】、【🔴 盤中跌破賣出 (NEW_SELL)】與【⚠️ 接近停損/突破警示 (距標 < 1%)】，於 13:25 試撮收盤前 15 分鐘及時推播 Telegram，提供充裕下單應對時間。

關鍵設計決策與技術折衷

A. 採用 SQLite 多表設計代替單一 CSV Beta

SQLite 支援結構化查詢與複合主鍵 Upsert 覆蓋更新，能高效儲存價格歷史 (`price_history`)、最適參數 (`supertrend_params`) 與最新交易訊號 (`stock_signals`)，避免資料重複並加速批次讀寫。

B. 逐日盯市 (MTM) 權益更新 vs. 僅平倉結算

傳統簡單回測常在平倉時一次性更新權益，會扭曲持倉期間的真實波動率。本系統採用每日盯市計價，使淨值曲線與風險指標 (Sharpe / Sortino / Ulcer Index) 更具實盤參考性。

C. 順勢過濾器選用：HMA vs. 傳統 SMA/EMA

HMA 藉由 WMA 權重進行延遲修正，反應速度快於傳統 SMA。系統保留自適應切換，供優化器自動決定是否啟用 HMA 過濾器。

D. SQLite 本地快取與 JSON 跨環境雙向同步 (Stateless CI/CD)

SQLite 資料庫 (`market_data.db`) 作為本地高效運算快取，加入 `.gitignore` 避免二進位 Commit 衝突與 Git 體積暴增；同時將最適參數自動雙向同步為輕量化 `data/optimized_params.json` 存入 Git 追蹤，使 GitHub Actions 等無狀態雲端環境能秒級恢復參數並進行即時掃描。

E. GitHub Actions 收盤延遲排程 (UTC 23:30) 與營業日快取校驗

考量美股收盤後 Yahoo 財經數據處理與封存時間，並徹底避開整點 (:00) 的 GitHub Actions 世界級排隊尖峰延遲，SuperTrend AI 自動排程設於 UTC 23:30 (台北時間隔日上午 07:30) 觸發，傳統策略排程設於 UTC 00:30 (台北時間 08:30)，確保數據完全就緒且能於數分鐘內快速分配伺服器；排程並優先依據 Cron 表達式辨識週六避免隊列延遲跨日；DataLoader 採用營業日覆蓋判定 (pd.bdate_range) 防止週中快取假命中，並自動將 yf.download 之 end 參數設為 end_date + 1 day。

F. 跨市場配置統一與雙向 Telegram 推播分流

全面統一由 data/must_have.json（美股）與 data/must_have_tw.json（台股 ETF 與國內基金）管理關注標的，廢棄多餘的獨立檔案；在批次推播時自動依市場分流發送兩則 Telegram 訊息，精準解決美股與台股休市日不同與貨幣符號混雜問題。

G. 純 Python 自包含渲染與 GitHub Pages 原生無狀態發布

捨棄繁瑣的現代前端 Node.js / Vite 建置流程，選擇以純 Python 生成自包含 HTML/CSS/Vanilla JS 檔案。此舉讓 GitHub Actions CI 完全免除額外執行環境安裝，將建置延遲壓縮至毫秒級；並配合 GitHub Pages 原生 Artifact 部署機制，避免在 Git Commit 中沉積大量 HTML 構建產物垃圾歷史。

H. 台股除權息還原與 TWSE 即時補丁融合機制 (消弭 1 日更新延遲)

針對 Yahoo Finance 對台股日線更新延遲（常落後 1 天）之問題，系統基於除權息調整的數學原理，以「最新除息日」作為安全拼接錨點。在最新除息日之後因無新的除息事件發生，TWSE 官方未還原價格與 yfinance 還原價格完全一致；DataLoader 在確認落後區間不跨越未調整除息日的前提下，自動調用 TWSE OpenAPI 即時盤後快照無縫補齊當日/缺漏 K 線，兼顧除權息歷史連續性與每日訊號的絕對即時性。

I. 台股盤中 13:10 即時訊號推播與記憶體虛擬 K 線拼接機制 (零污染架構)

台股交易時間為 09:00～13:30（13:25 開始收盤試撮）。盤中 13:10 日 K 線型態已完成 95% 以上，既能準確反應當日日線趨勢，又保有 15 分鐘的充裕實盤掛單窗口，消弭隔日開盤跳空風險。架構上嚴格恪守「零污染原則」，即時數據僅於記憶體中臨時拼接進行推論，絕不寫入 SQLite 歷史結算庫，實現盤中決策與盤後結算的乾淨解耦。

非功能性需求要求

  • **可重現性：** 指定 Monte Carlo 模擬 Seed 後，多次回測數據完全一致。
  • **效能要求：** 快取讀取與回測流程執行完畢限制在 3 秒內。
  • **並行計算：** 批次優化腳本支援多執行緒並行運算。

已知系統限制 Constraint

  • **小時線歷史窗口自動截斷：** Yahoo Finance 的 1-Hour (小時) 資料僅提供最近 730 天，當請求時間超過 730 天時系統會自動截斷起始日期在 730 天內。
  • **無融券借券成本：** 短期交易或 Short 反向交易並未加計利息與融券費用，空頭模擬可能偏向樂觀。
